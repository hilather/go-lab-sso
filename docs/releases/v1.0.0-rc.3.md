They do not rewrite rc.1/rc.2 history.

LabSSO is a **laboratory identity provider**. It is not production SSO and does not impersonate vendor hostnames.

## Highlights

1.0.0-rc.3 replaces the shared `lab-totp` stub with RFC 6238 file-ref TOTP ([ADR 0011](../adr/0011-file-ref-totp.md)) and lands Mira’s Matt-approved Lab* operator chrome on the existing SPA ([#3](https://github.com/hilather/go-lab-sso/pull/3)).

- Durable seeds are optional `users[].totpSecretRef` (base32 file). Enroll / rotate / clear is an in-memory overlay so REST, MCP, and the operator Users view can mutate MFA without the process writing secret files.
- After MFA, OIDC emits `amr` / `acr`; SAML / WS-Fed emit `TimeSyncToken`. `lab-totp` is rejected.
- Operator chrome is a restyle of the existing SPA plus binding session expire REST that already existed. Data-plane `/login` `/consent` are a 380px lab IdP card, not the operator rail.

## Added

- File-ref TOTP ([ADR 0011](../adr/0011-file-ref-totp.md)): RFC 6238 SHA-1, 30s, 6 digits, process clock, ±1 step. Optional `users[].totpSecretRef`. In-memory enroll/rotate/clear overlay on `oidc.Runtime`. Typed `POST /v1/auth/mfa` / `sso_auth_mfa_set`, `POST /v1/users/{id}/totp:enroll` / `sso_user_totp_enroll`, `POST /v1/users/{id}/totp:clear` / `sso_user_totp_clear`. Operator Users view paints `totp.configured` / `totp.source` / `totpSecretRef` (path). Enroll returns `secret` + `otpauth` once on the REST/MCP result. Fixture `testdata/config/valid/totp-alice.yaml` (`8ad0560`).

## Changed

- Operator chrome (Mira afters, [#3](https://github.com/hilather/go-lab-sso/pull/3)): Lab* family shell in `internal/web` — 56px masthead, 196px IDENTITY/LAB rail, IBM Plex via Google Fonts CSS CDN (no third-party JS). Sessions list/inspector paints LoginSession only (`ID`, `UserID`, `Username`, `Expires`, `MFACompleted`) and binds existing `POST /v1/sessions/{id}:expire` and `POST /v1/sessions:expire-all` (no `expectedRevision`). Users list/inspector binds existing `POST /v1/auth/mfa`, `totp:enroll`, and `totp:clear`. Leftover groups/clients/status/audit inherit the shell and keep JSON bodies. Data-plane `/login` `/consent` are a 380px lab IdP card (generic clothes: LabSSO / Sign in), not the operator rail. Cookie `labsso_session` + CSRF `X-LabSSO-CSRF` unchanged. `spec.ui.enabled: false` still 404s `GET /` only (`cf99370`).

## Fixed

- None versus v1.0.0-rc.2. `lab-totp` rejection is the TOTP replacement (Added / Removed).

## Removed or deprecated

- Shared literal `lab-totp` is rejected. Login with `mfa.mode: always` now requires a file-ref seed or an overlay enroll.

## Security

- Secrets stay file refs. Overlay TOTP seeds are never written to disk and must not appear in export, audit, logs, or MCP resources. Enroll returns the secret once on the tool/REST result ([docs/20-threat-model.md](../20-threat-model.md) T19).
- `lab-totp` is no longer a shared backdoor.
- Operator SPA still stores no tokens in `localStorage`, `sessionStorage`, IndexedDB, or the URL. Enroll seed is dismissible page memory (`lastEnroll`).
- No new listeners. Management stays bearer or cookie+CSRF. Data-plane login HTML stays first-party.
- No LabNTP time bus. TOTP uses the process clock.

## REST API

- New: `POST /v1/auth/mfa` (typed mode merge; `expectedRevision` + reason), `POST /v1/users/{id}/totp:enroll`, `POST /v1/users/{id}/totp:clear`.
- Unchanged: `POST /v1/sessions/{id}:expire` and `POST /v1/sessions:expire-all` (chrome binds them; REST already omitted `expectedRevision`).
- REST remains an adapter over the shared registry. No independent business logic in handlers.

## MCP API and protocol compatibility

- New twins: `sso_auth_mfa_set`, `sso_user_totp_enroll`, `sso_user_totp_clear`. Enroll is not idempotent; the seed is on the tool result only — never a resource.
- Protocol pin remains **2026-07-28**. Official SDK `github.com/modelcontextprotocol/go-sdk` **v1.7.0**. `allowLegacyClients: true` is still required for MCPJungle.
- MCP is not a REST proxy.

## Configuration and schema

- Additive optional `users[].totpSecretRef` (base32 file path). Unknown fields still reject. `spec.auth.mfa.mode` is unchanged (`never` | `always` | `force-fail`).
- Missing file, bad base32, and newline-in-ref fail closed at load. Fixture pack: `totp-alice.yaml` plus invalid `totp-missing-file`, `totp-bad-base32`, `totp-newline-ref`, `unknown-totp-field`.
- Overlay enroll dies on restart and `state:reset`. Clothes swap does not drop overlay. Changing `totpSecretRef` or removing the user does.
- Canonical export does not include overlay seeds.

## Operator SPA and data-plane login

- Chrome implements approved Mira afters. It is not a first-UI without review. Checklist: [docs/22-operator-spa.md](../22-operator-spa.md).
- Masthead binds existing reads: issuer from `GET /v1/status`, ready from `GET /v1/health/ready`, actor from `GET /v1/session`, MFA mode from `GET /v1/state` `canonical.spec.auth.mfa.mode`.
- Sessions do not paint `clientId`, `protocol`, `issued`, or `scope` until `GET /v1/sessions` returns them.
- Data-plane MFA field `name="mfa"` still appears only on the two-submit step.

## Residual

See [docs/known-limitations.md](../known-limitations.md).

- Integrator pin in `hilather/mcp-integration-lab` is **not** this tag. INT-001 is last and is not implemented from this repo.
- TOTP overlay enroll is process memory; restart and `state:reset` drop it. Durable MFA needs `totpSecretRef`.
- `token:mint` stays password-only (no `amr` / `acr`). No `acr_values` step-up.
- Leftover groups/clients/status/audit stay JSON dumps in the operator shell.
- SCIM outbound remains design-only. No inbound SCIM server.
- No tag-triggered GHCR publish in this repository. Image `ghcr.io/hilather/labsso` may be unpublished until a human builds and marks the package public.
- linux/arm64 is not promised from this tree.
- `labsso version` stays `0.0.0-dev` without ldflags.

## Deployment and operations

Image `ghcr.io/hilather/labsso` (scratch, UID 65532, read-only, `cap_drop ALL`) when a human builds it. Compose still publishes host `443:10443` and loopback management `127.0.0.1:8080:8080`. Dest-443. No LabNTP bus. One exact issuer from `LAB_PUBLIC_HOST` plus published HTTPS port (omit port iff 443).

Reload or restart onto this tag to pick up TOTP verification and chrome. Overlay enrolls do not survive that restart.

## Compatibility and migration

- Upgrade from `v1.0.0-rc.2`: rebuild/restart onto this tag. Bootstrap YAML needs no migration unless you want durable MFA — add `users[].totpSecretRef` or enroll after start.
- Labs that submitted the literal `lab-totp` under `mfa.mode: always` will fail closed until they file-ref or enroll.
- Rollback: restore the previous image/tag pin. `lab-totp` returns. Overlay enrolls and login sessions discard on restart (ADR 0003).
- Config remains `labsso.dev/v1alpha1`.
